# mlir/lib/Reducer

## Purpose
Implements the `mlir-reduce` IR minimization tool. Given an MLIR file that triggers a bug (checked by an external tester script), this library applies reduction passes to produce the smallest IR that still reproduces the bug. Uses a tree-based reduction search strategy.

## Key Files
| File | Description |
|------|-------------|
| `ReductionNode.cpp` | `ReductionNode`: a node in the reduction tree; holds an IR variant (module clone), its interestingness result, and child nodes generated by applying reduction passes |
| `ReductionTreePass.cpp` | `ReductionTreePass`: the main reduction driver; performs a tree search (DFS/BFS) over `ReductionNode`s, invoking the tester on each candidate and pruning uninteresting branches |
| `OptReductionPass.cpp` | `OptReductionPass`: a reduction pass that runs MLIR optimization passes and checks if the result is still interesting (reduces by simplification) |
| `Tester.cpp` | `Tester`: subprocess wrapper that invokes the user-provided external test script on an IR snippet and returns whether the snippet is "interesting" (i.e., still triggers the bug) |

## For AI Agents

### Working In This Directory
- Reduction passes implement `mlir::Pass` but are specialized for the reducer; they produce multiple candidate outputs rather than a single transformed IR.
- The tester script path and arguments are specified via `--test` and `--test-arg` flags.
- New reduction strategies (e.g., block merging, op erasure) are implemented as new pass subclasses registered with the reducer pipeline.

### Common Patterns
- `ReductionNode` clones the module before each reduction attempt to preserve the original for backtracking.
- The tree structure allows the reducer to explore multiple reduction strategies in parallel.

## Dependencies

### Internal
- `mlir/lib/IR/` — module cloning, op erasure
- `mlir/lib/Pass/` — pass manager for `OptReductionPass`

### External
- `llvm/lib/Support` — `llvm::sys::ExecuteAndWait` (subprocess), ADT
